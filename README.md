# ARM DRIVE

Готовый проект: Next.js + React + TypeScript, отдельный API и админ-панель на Node.js / Express, SQLite. Основной язык — армянский; русский и английский доступны по переключателю и прямым адресам. Клиент связывается с владельцем по телефону, WhatsApp или email; сайт не принимает платежи и не создаёт заявки.

## Запуск в VS Code

1. Установи Node.js **24** и VS Code.
2. Распакуй архив и открой папку `arm-drive` через **File → Open Folder**.
3. Открой **Terminal → New Terminal** и выполни:

```bash
npm ci
```

4. Скопируй `.env.example` в `.env`. На Mac / Linux:

```bash
cp .env.example .env
```

На Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

5. Создай первого администратора:

```bash
npm run admin:create
```

Укажи логин латиницей или email и дважды введи пароль минимум из 12 символов. Пароль в терминале не отображается. В проекте нет стандартного логина или пароля.

6. Запусти сайт и API одной командой:

```bash
npm run dev
```

Сайт: http://localhost:3000/ · Админка: http://localhost:3000/admin/ · API: http://localhost:4000/api/health

Страницы: `/hy/`, `/ru/`, `/en/`. Корневой адрес `/` открывает сохранённый выбор посетителя или основной язык из настроек. Для адресов языков используются статические страницы Next.js.

Если нужно открыть разработку с телефона в одной Wi-Fi сети, задайте IP Mac в `DEV_ALLOWED_ORIGINS`, `WEB_ORIGIN=http://IP:3000` и `NEXT_PUBLIC_API_URL=http://IP:4000`, а `HOST=0.0.0.0`. Перезапустите разработку. Для обычной работы на Mac используйте localhost и настройки по умолчанию.

Остановить серверы: **Ctrl+C**. Данные сохраняются между запусками.

## Что умеет администратор

- Добавлять, изменять и удалять машины.
- Заполнять названия и описания на HY / RU / EN.
- Изменять цену за сутки, залог, год, места, коробку, топливо и категорию.
- Менять порядок машин, скрывать публикацию и временно отключать доступность.
- Загружать PNG, JPEG, WebP до 10 MB; добавлять несколько фотографий и менять их порядок.
- Использовать HTTPS-ссылки на фотографии. Первое изображение — обложка карточки.
- Редактировать бренд, логотип, телефон, WhatsApp, email, адреса, язык по умолчанию и главное изображение.
- Редактировать тексты сайта, кнопки, FAQ и переводы во вкладке «Тексты и переводы».
- Добавлять и удалять других администраторов; менять свой пароль.
- Экспортировать и восстанавливать содержимое в JSON.
- Удалять неиспользуемые загруженные фото. Используемое фото защищено от удаления, пока оно привязано к машине, логотипу или главному экрану.

В админке также есть переключатель трёх языков. Изменения становятся видны на публичной стороне после обновления страницы. При редактировании в нескольких вкладках сохраняется последнее сохранение.

## Первое наполнение

В базе изначально находятся три **демонстрационные** машины и сгенерированные изображения. Они обозначены как примеры. Удали их или замени своими, заполни характеристики и настоящие условия. Сними флажок «Демонстрационный пример» для реальных машин.

Добавь контакты во вкладке «Настройки сайта». Используй международный формат телефона, например `+374 …`. WhatsApp — номер, на котором активен WhatsApp. Пока контакты пустые, сайт честно сообщает, что они ещё не добавлены.

При выборе машины открываются фотографии, место выдачи и расчёт по датам. WhatsApp и email получают подготовленный текст с машиной, местом выдачи, датами и стоимостью. Нажатие кнопки открывает сервис клиента; сайт сам сообщения не отправляет. Залог показывается отдельно и не прибавляется к стоимости аренды. Минимальный срок расчёта — один день.

FAQ содержит нейтральные формулировки до внесения твоих реальных требований, страховки и условий аренды. Все эти тексты доступны в редакторе.

После установки / запуска автоматически появляются:

- `node_modules/` — зависимости.
- `.next/` — промежуточная сборка Next.js.
- `out/` — готовые страницы и ресурсы после `npm run build`.

## Размещение в интернете

Пошаговая инструкция для домена, HTTPS и постоянного хранения данных: [DEPLOYMENT.md](DEPLOYMENT.md). В проект добавлены `compose.yaml` и `deploy/Caddyfile`. Конфигурация подготовлена, но реальное размещение пока не выполнено.


Самый простой вариант — один хостинг с **Node.js 24** и постоянным диском. Next.js собирается в статические страницы, а Express обслуживает эти страницы, API, фотографии и админку с одного адреса.

1. Загрузить исходники и выполнить `npm ci`.
2. Создать `.env`, указать настоящий адрес сайта в `WEB_ORIGIN`.
3. Настроить HTTPS и `COOKIE_SECURE=true`.
4. За доверенным reverse proxy поставить `TRUST_PROXY=true`; `HOST=0.0.0.0` — только если сервер должен слушать внешний интерфейс / контейнер.
5. Выполнить `npm run admin:create`, `npm run build`, затем `npm start`.
6. Использовать постоянный диск для `DATA_DIR`, процесс-менеджер и регулярные резервные копии.

`NEXT_PUBLIC_API_URL` оставь пустым при размещении всего на одном адресе. В разработке фронтенд автоматически использует `http://localhost:4000`.

Если размещать фронтенд и API отдельно, установи `NEXT_PUBLIC_API_URL=https://api.your-domain.example` **до сборки**. Укажи адрес фронтенда в `WEB_ORIGIN`. Для cookie-авторизации используй один сайт: например `www.example.com` и `api.example.com`, оба HTTPS. Между совершенно разными доменами браузер может блокировать сессии.

Текущий адрес ARM DRIVE в Sites показывает статическую сборку Next.js. Внешний Node.js API к этому адресу ещё не подключён. Поэтому там доступны дизайн и демо-автопарк, но вход и сохранение изменений в админке заработают после подключения API. В архиве API полностью реализован и проверен. Он запускается локально вместе с сайтом.

## Docker

```bash
docker build -t arm-drive .
docker run --rm -it -v arm-drive-data:/app/data arm-drive npm run admin:create
docker run -d --name arm-drive -p 4000:4000 -v arm-drive-data:/app/data --env-file .env arm-drive
```

Для контейнера поставь `HOST=0.0.0.0` в `.env`. Постоянный том `arm-drive-data` хранит базу и фото. В рабочем размещении перед сервером нужен HTTPS reverse proxy.

## Как устроен доступ

API проверяет сессию на каждой административной операции. Пароли хешируются через scrypt с солью. Сессия хранится в HTTP-only cookie на 8 часов, а её токен — в базе в хешированном виде. Для изменений требуется CSRF-токен. Вход ограничен по частоте; ввод проверяется на сервере. Нельзя удалить собственный административный аккаунт. Удаление администратора удаляет его сессии.

Администратор управляет всем предоставленным содержимым сайта. Изменение дизайна, структуры разделов или алгоритмов делается в исходниках в VS Code.

## Проверка

Проект проверяется сборкой Next.js, TypeScript и интеграционным тестом: вход, отказ без сессии, CSRF, CRUD машин, видимость, перевод, валидация цен, загрузка фото, защита используемых фото, backup / restore, logout. Визуальная проверка реальным браузером в этой среде не выполнялась.
